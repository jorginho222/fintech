# Fintech API

A REST API for business credit. Companies register, apply for credit, accept loan proposals, and pay them back in installments. Credit applications are checked by an external credit bureau, which reports results back through a webhook.

Built with **Symfony 7.3** and **PHP 8.3**, following **Domain-Driven Design** and **Clean Architecture**. The whole development environment runs in Docker.

## Features

- **Company accounts:** registration, JWT login, token refresh, and logout with a token denylist
- **Credit applications:** a company applies for credit; the application is sent asynchronously through RabbitMQ to the credit bureau
- **Credit bureau webhook:** the bureau posts its decision back, authenticated with a shared secret
- **Credit requests and installments:** confirm a proposal, list and pay pending installments, and get a company's total debt
- **Scheduled jobs:** daily tasks expire stale proposals, mark overdue installments, and clean up expired revoked tokens

## Tech stack

| Component | Used for |
|---|---|
| Symfony 7.3 / PHP 8.3 | Application framework |
| PostgreSQL 16 | Main database (Doctrine ORM, XML mappings) |
| RabbitMQ 3.13 | Async message transport (Symfony Messenger) |
| Symfony Scheduler | Recurring daily jobs |
| LexikJWTAuthenticationBundle | API authentication |
| Nginx | HTTP server in front of PHP-FPM |
| PHPUnit | Unit, integration and functional tests |

## Architecture

The code is organized by module first, then by layer:

```
src/
  Company/          # Company accounts and authentication
  CreditRequest/    # Applications, credit requests and installments
  Shared/           # Code shared across modules
    {Module}/
      Domain/           # Entities, value objects, repository interfaces — no framework code
      Application/      # Use cases (one class each) and DTOs
      Infrastructure/   # Doctrine mappings and repositories, messaging, security
      UI/               # HTTP controllers and console commands
```

Domain classes have no framework dependencies: Doctrine mappings are XML files in each module's `Infrastructure/Persistence/Doctrine/Mapping/`, and entity IDs are UUIDs generated by the application.

## Installation

### Requirements

- Docker with Docker Compose
- Make
- OpenSSL (to generate the JWT keys)

### 1. Clone the repository

```bash
git clone git@github.com:jorginho222/fintech.git
cd fintech
```

### 2. Configure the environment

```bash
cp .env.example .env
```

Then edit `.env`. With the default Docker setup the values are:

| Variable | Value |
|---|---|
| `APP_ENV` | `dev` |
| `APP_SECRET` | any random string |
| `DATABASE_URL` | `postgresql://fintech:secret@postgres:5432/fintech?serverVersion=16&charset=utf8` |
| `MESSENGER_TRANSPORT_DSN` | `amqp://guest:guest@rabbitmq:5672/%2f/messages` |
| `JWT_SECRET_KEY` | `%kernel.project_dir%/config/jwt/private.pem` |
| `JWT_PUBLIC_KEY` | `%kernel.project_dir%/config/jwt/public.pem` |
| `JWT_PASSPHRASE` | the passphrase you use in step 4 |
| `JWT_TOKEN_TTL` / `JWT_REFRESH_TOKEN_TTL` | token lifetimes in seconds, e.g. `3600` / `2592000` |
| `MAILER_DSN` | your SMTP server |
| `MAILER_FROM_ADDRESS` | the sender address for outgoing mail |
| `CREDIT_BUREAU_SIMULATION_WEBHOOK_URL` | the credit bureau endpoint that receives applications |
| `CREDIT_BUREAU_WEBHOOK_SECRET` | the shared secret the bureau sends with its webhook calls |

### 3. Build and start the containers

```bash
make build
make up
```

This starts:

| Service | Address |
|---|---|
| API (nginx) | http://localhost:8080 |
| Adminer (DB admin) | http://localhost:8081 |
| RabbitMQ management | http://localhost:15672 (`guest` / `guest`) |
| PostgreSQL | `localhost:5432` |
| Messenger worker | consumes the `async` queue and both schedules |

### 4. Install dependencies and generate JWT keys

```bash
make install
docker compose exec php bin/console lexik:jwt:generate-keypair
```

The keys are written to `config/jwt/` and encrypted with `JWT_PASSPHRASE`. They are git-ignored.

### 5. Run the migrations

```bash
make migrate
```

The API is now available at `http://localhost:8080/api/v1`.

## API overview

All routes are under `/api/v1`. Except for registration, login and refresh, every request needs an `Authorization: Bearer <token>` header.

| Method | Path | Description |
|---|---|---|
| `POST` | `/company_registration` | Register a company |
| `POST` | `/login` | Get an access and refresh token |
| `POST` | `/refresh` | Exchange a refresh token for a new access token |
| `POST` | `/logout` | Revoke the current token |
| `POST` | `/credit-request/apply` | Apply for credit |
| `GET` | `/credit-request-application/search` | List credit applications |
| `PUT` | `/credit-request-application-update` | Credit bureau webhook (shared-secret auth) |
| `GET` | `/credit-request/search` | List credit requests |
| `GET` | `/credit-request/{id}` | Get a credit request |
| `PUT` | `/credit-request/{id}/confirm` | Confirm a credit proposal |
| `GET` | `/installment/pending-to-pay/search` | List pending installments |
| `PUT` | `/installment/{id}/pay` | Pay an installment |
| `GET` | `/company-total-debt` | Get the company's total outstanding debt |

## Testing

Create the test database once:

```bash
docker compose exec php bin/console doctrine:database:create --env=test
docker compose exec php bin/console doctrine:migrations:migrate --env=test --no-interaction
```

Run the tests:

```bash
make test                                                       # all suites
docker compose exec php bin/phpunit --testsuite Unit            # domain logic, no DB
docker compose exec php bin/phpunit --testsuite Integration     # repositories against the test DB
docker compose exec php bin/phpunit --testsuite Functional      # HTTP-level tests
```

Each test runs inside a transaction that is rolled back afterwards, so tests don't leave data behind.
